# 開場五件事：第一版只准做這五樣

> 這份解的病：**AI 什麼都答得出來，所以你想到什麼它就加什麼**，兩週後你有一個
> 半成品的登入、半成品的付款、半成品的通知，而**沒有一件事是可以給人用的**。

## 給 AI 的指示（這一段不要刪）

**專案開始時，先跟使用者一起把下面五格填滿，並且只填五格。**
**填完之後，使用者提出的任何新東西，一律先問「這要取代五件裡的哪一件」——
不准直接變成第六件。**

🔴 **這一份的重點不是那五件是什麼，是那張「不做」的清單存在。**
沒有「不做」清單的專案，範圍不會停止長大，因為每一個新想法單看都很合理。

---

## 五格

| # | 這一版要做到的事（一句話，白話） | 做完了要怎麼看出來 |
|---|---|---|
| 1 | | |
| 2 | | |
| 3 | | |
| 4 | | |
| 5 | | |

**右邊那一欄不准寫「程式寫完」。** 要寫一個**看得到的東西**：
✅「我打開網頁，看到我昨天存的那三筆」
❌「資料庫寫入功能完成」

---

## 🔴 排序的判準：哪一件是第 1 件

**問這一題：這五件裡，哪一件拿掉之後，剩下四件就沒有意義了？**

那一件就是第 1 件，而且要先做完它才碰第 2 件。

例子：一個記帳的東西，五件是「輸入一筆／看到清單／分類／統計圖／匯出」。
把「輸入一筆」拿掉，其他四件全部沒東西可做 ⇒ 它是第 1 件。
把「統計圖」拿掉，其他四件照樣成立 ⇒ 它是第 5 件。

🔴 **不准五件同時開工。** 五件同時做到一半，等於零件做完——而這是新手專案最常見的死法。

**如果答案不是剛好一個，照這兩條走（不要硬湊一個）：**

- **沒有任何一件拿掉會讓其他四件失去意義** ⇒ 五件互相獨立。
  改用這一題排：**哪一件最快能讓你從頭到尾走完一次、看到一個真的結果？** 那一件先做。
- **有兩件以上拿掉都會讓其他失去意義** ⇒ 它們是同一件事的兩半，被拆錯了。
  先合成一件，然後你只用了四格——**空著就空著，不要補一個湊滿五件。**

🔴 **「五件」是上限，不是配額。** 三件做得完的事寫成五件，是把範圍膨脹寫進計畫裡。

---

## 不做清單（這一格比上面那張表重要）

> 每次有人（包括 AI 自己）提出一個新東西而它不在五件裡，就抄一列到這裡。
> **這不是拒絕，是排隊。**

| 想到的東西 | 為什麼這一版不做 | 什麼情況會把它排進來 |
|---|---|---|
| （範例）使用者註冊登入 | 這一版只有我自己用，登入不解決任何我現在的麻煩 | 要給第二個人用的那一天 |
| （範例）手機 app | 網頁在手機上打得開就夠了 | 有人明確說他要在沒網路的地方用 |

🔴 **「什麼情況會把它排進來」不准寫「以後」。** 要寫一個**具體會發生的事**。
寫不出來的那一項，很可能永遠不需要做——那正是這一格的價值。

---

## 🔴 兩條硬規矩

**一、第六件事一律先問「要換掉哪一件」。**
使用者不一定要換（他可以說「那就六件」），但這一問要問出來，
因為**範圍膨脹幾乎都不是一次決定的，是十次「順便」累積的**。

**二、五件裡有任何一件做完之後你沒有辦法給出「看得到的東西」⇒ 那一件寫錯了，回去重寫。**
不是回去多寫程式，是回去改那一句描述。

---

## 這份文件刻意不做的事

- **不規定五件事要多大。** 一週做得完還是三個月做得完，都可以——
  重點是**數量封頂**，不是規模封頂。真的太大，第 1 件會自己撞牆告訴你。
- **不管技術選擇。** 用哪個語言、放哪裡、要不要資料庫，這份不碰。
  那些是做第 1 件的時候順便決定的事，先決定會變成憑空想像。
