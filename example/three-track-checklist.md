# 範例：待辦清單命令列工具——三軌檢查表填寫範例

> 這是 [`docs/three-track-checklist.md`](../docs/three-track-checklist.md) 填完的樣子，
> 對象是 [`example/ACCEPTANCE_FIRST.md`](./ACCEPTANCE_FIRST.md) 那批「立即寫入」的改動。

## 軌一：TDD——零件對不對

- [x] 這條測試斷言的對象，是不是被測的那一個？
      是——`test_write_is_immediate` 直接檢查「新增後 0.1 秒內檔案的修改時間有沒有更新」，
      不是檢查「檔案存不存在」（存在但沒更新這種情況會被漏掉，所以特別挑了修改時間）。
- [x] 拔除演練：把「立即寫入」改回「每 10 秒排程寫入」，這條測試變紅了。
- [x] 陽性對照：故意把測試裡的等待時間改成 20 秒（超過排程週期），確認舊版程式碼在這個
      條件下測試會過——證明測試本身能分辨「立即」跟「排程」，不是隨便都過。

## 軌二：BDD——使用者真的拿到他要的了嗎

- [x] 把這批東西擺回使用者情境：「使用者輸入一筆待辦事項後，立刻關掉終端機，
      重新打開程式，剛剛那筆待辦事項還在。」走過一遍手動測試，結果符合。
- [x] 正式使用路徑裡確實會呼叫到新的寫入函式——`add` 指令的最後一步就是呼叫它，
      不是只有測試檔案自己呼叫。

## 軌三：GDD——圖是不是真的

- [x] 這支工具的接線圖只有一張（`docs/ARCHITECTURE.md` 裡的一段文字說明：
      指令列 → 記憶體中的清單 → 儲存模組 → 磁碟檔案），改完後這張圖不用更新內容，
      因為資料流向沒有變，只有「什麼時候寫」變了——圖上如果畫的是時序就要更新，
      這裡圖只到「流向」的顆粒度，判斷後不需要動。
- [x] 拔除演練：如果把這次新加的「立即寫入」邏輯整段移除，`test_write_is_immediate`
      會紅，但其他測試（`add`、`list`、`done` 指令本身）全部維持綠——證明這是一個
      可以乾淨插拔的改動，沒有把別的功能焊在一起。
